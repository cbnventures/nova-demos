# Policies

A <Terminology title="Sealed rule telling Marshal how to handle events" to="/docs/terminology#policy">policy</Terminology> is a written rule about how <Terminology title="Automated repository governance system filing and sealing policies" to="/docs/terminology#marshal">Marshal</Terminology> handles a class of events on a repository — stale issues, overdue PRs, support requests by tier, scheduled handovers.

## Default policies

- **Thread archival** — close and <Terminology title="Marshal's closing mark once a condition is met" to="/docs/terminology#seal">seal</Terminology> threads inactive for N days
- **<Terminology title="Sponsor, Contributor, or Public classification on a request" to="/docs/terminology#access-tier">Access tiers</Terminology>** — route incoming work by sponsor / contributor / public
- **Scheduled <Terminology title="Marshal's scheduled maintenance run without manual work" to="/docs/terminology#stewardship">stewardship</Terminology>** — run cleanups, audits, and rollovers on a cron
- **<Terminology title="Mark Marshal leaves each time it acts" to="/docs/terminology#stamp">Stamp</Terminology> <Terminology title="Org-wide record joining every repository's docket" to="/docs/terminology#ledger">ledger</Terminology>** — every <Terminology title="Automated repository governance system filing and sealing policies" to="/docs/terminology#marshal">Marshal</Terminology> action records its own line in the public record

## Filing a policy

Each <Terminology title="Sealed rule telling Marshal how to handle events" to="/docs/terminology#policy">policy</Terminology> is a YAML block, signed at the bottom, <Terminology title="Submitting a policy or job to Marshal's docket" to="/docs/terminology#filing">filed</Terminology> by <Terminology title="Automated repository governance system filing and sealing policies" to="/docs/terminology#marshal">Marshal</Terminology> at the top of the next hour. <Terminology title="Automated repository governance system filing and sealing policies" to="/docs/terminology#marshal">Marshal</Terminology> reads only what is <Terminology title="Submitting a policy or job to Marshal's docket" to="/docs/terminology#filing">filed</Terminology> and <Terminology title="Mark Marshal leaves each time it acts" to="/docs/terminology#stamp">stamps</Terminology> only what is <Terminology title="Marshal's closing mark once a condition is met" to="/docs/terminology#seal">sealed</Terminology>.
