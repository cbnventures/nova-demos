# Build Pipeline

Foundry builds <Terminology title="Foundry project declared in a .grain manifest" to="/docs/terminology#workspace">workspaces</Terminology> in five stages: resolve, cache check, compile, link, and verify. Two tools drive this pipeline — <Terminology title="Content-addressable build cache skipping unchanged packages" to="/docs/terminology#quench">Quench</Terminology> handles caching, <Terminology title="Parallel task runner building independent packages together" to="/docs/terminology#bellows">Bellows</Terminology> handles parallelism.

## The Forge Lifecycle

Every `foundry ignite` invocation follows the same sequence:

1. **Resolve.** <Terminology title="Resolves the dependency graph with query tools" to="/docs/terminology#tongs">Tongs</Terminology> reads the manifest and builds the dependency graph.
2. **Cache check.** <Terminology title="Content-addressable build cache skipping unchanged packages" to="/docs/terminology#quench">Quench</Terminology> hashes every source file, dependency version, and manifest directive. If the hash matches a previous build, the package is skipped.
3. **Compile.** <Terminology title="Compiler turning package source into build output" to="/docs/terminology#smelter">Smelter</Terminology> compiles the source files for each package.
4. **Link.** Cross-package references are resolved and import aliases are wired.
5. **Verify.** <Terminology title="Foundry's linting engine with 380+ rules" to="/docs/terminology#warden">Warden</Terminology> runs against the compiled output. <Terminology title="Generates test scaffolds from exported type signatures" to="/docs/terminology#crucible">Crucible</Terminology> runs generated tests if configured.

## Quench Caching

<Terminology title="Content-addressable build cache skipping unchanged packages" to="/docs/terminology#quench">Quench</Terminology> is a content-addressable build cache. It does not use file timestamps — timestamps are unreliable across machines and after version control operations.

Instead, <Terminology title="Content-addressable build cache skipping unchanged packages" to="/docs/terminology#quench">Quench</Terminology> hashes three inputs:

| Input               | Description                                                                                                                                                                                                                                                                                        |
|---------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Source content      | SHA-256 of every file in the package `src/` directory.                                                                                                                                                                                                                                             |
| Dependency versions | The resolved version string of every dependency in the <Terminology title="Resolves the dependency graph with query tools" to="/docs/terminology#tongs">Tongs</Terminology> graph.                                                                                                                 |
| Manifest directives | The <Terminology title="Foundry's linting engine with 380+ rules" to="/docs/terminology#warden">Warden</Terminology> rules, <Terminology title="Compiler turning package source into build output" to="/docs/terminology#smelter">Smelter</Terminology> config, and target from the `.grain` file. |

If all three hashes match a cached build, <Terminology title="Content-addressable build cache skipping unchanged packages" to="/docs/terminology#quench">Quench</Terminology> restores the artifacts and skips compilation entirely.

```text title="Cache status output"
$ foundry quench status
  core       [HIT]  abc12f → cached 2m ago
  auth       [HIT]  def34a → cached 2m ago
  api        [MISS] ghi56b → source changed (src/routes/health.al)
  web        [HIT]  jkl78c → cached 14m ago
  gateway    [WAIT] depends on api (MISS), must rebuild
```

### Warm vs Cold Forges

A cold <Terminology title="Running foundry ignite to generate workspace artifacts" to="/docs/terminology#forge--ignite">forge</Terminology> runs with an empty cache. Every package compiles from scratch.

A warm <Terminology title="Running foundry ignite to generate workspace artifacts" to="/docs/terminology#forge--ignite">forge</Terminology> runs when most hashes match — only changed packages and their downstream dependents rebuild.

| Workspace Size | Cold Forge | Warm Forge |
|----------------|------------|------------|
| 10 packages    | 8.1s       | 1.2s       |
| 50 packages    | 14.7s      | 1.8s       |
| 100 packages   | 28.3s      | 2.1s       |
| 200 packages   | 52.6s      | 3.4s       |

### Cache Maintenance

Prune old cache entries to reclaim disk space:

```bash title="Remove entries older than 7 days"
foundry quench prune --older-than 7d
```

## Bellows Parallelism

<Terminology title="Parallel task runner building independent packages together" to="/docs/terminology#bellows">Bellows</Terminology> reads the <Terminology title="Resolves the dependency graph with query tools" to="/docs/terminology#tongs">Tongs</Terminology> dependency graph and schedules packages in <Terminology title="Group of packages Bellows builds in parallel" to="/docs/terminology#wave">waves</Terminology>. Independent packages build simultaneously while dependent packages wait for their prerequisites.

<Tabs>
<TabItem value="local" label="Local Development" default>

```bash title="Run a parallel forge locally"
foundry ignite
```

<Terminology title="Parallel task runner building independent packages together" to="/docs/terminology#bellows">Bellows</Terminology> auto-detects the number of CPU cores and fans work accordingly. Override with the `FOUNDRY_PARALLELISM` environment variable.

</TabItem>
<TabItem value="ci" label="Conduit (CI)">

```bash title="Run a forge in Conduit"
foundry ignite --ci
```

In CI mode, Foundry produces structured JSON output for pipeline integration, disables interactive prompts, and respects the `FOUNDRY_CACHE_DIR` variable for shared cache directories.

</TabItem>
</Tabs>

### Execution Order

<Terminology title="Parallel task runner building independent packages together" to="/docs/terminology#bellows">Bellows</Terminology> groups packages into <Terminology title="Group of packages Bellows builds in parallel" to="/docs/terminology#wave">waves</Terminology> based on the dependency graph:

```text title="Bellows execution log"
$ foundry bellows build --verbose
  Wave 1: core (no dependencies)
  Wave 2: auth, cli, docs (depend on core)
  Wave 3: api, web (depend on core + auth)
  Wave 4: gateway (depends on api + auth)

  Total: 4 waves, 7 packages, 3.4s (warm)
```

Packages within the same <Terminology title="Group of packages Bellows builds in parallel" to="/docs/terminology#wave">wave</Terminology> run in parallel. <Terminology title="Group of packages Bellows builds in parallel" to="/docs/terminology#wave">Waves</Terminology> execute sequentially.

The total build time is the sum of the longest package in each <Terminology title="Group of packages Bellows builds in parallel" to="/docs/terminology#wave">wave</Terminology> — not the sum of all packages.

## Build Strategies

| Strategy                                                                                                                                  | Command                            | Use Case                                  |
|-------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------|-------------------------------------------|
| Full <Terminology title="Running foundry ignite to generate workspace artifacts" to="/docs/terminology#forge--ignite">forge</Terminology> | `foundry ignite`                   | Generate all artifacts from the manifest. |
| Incremental                                                                                                                               | `foundry ignite --incremental`     | Only rebuild changed packages.            |
| Single package                                                                                                                            | `foundry bellows build --only api` | Build one package and its dependencies.   |
| Dry run                                                                                                                                   | `foundry ignite --dry-run`         | Preview output without writing files.     |
