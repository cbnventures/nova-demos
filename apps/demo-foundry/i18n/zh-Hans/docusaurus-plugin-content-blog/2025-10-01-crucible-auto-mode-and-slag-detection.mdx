Foundry 2.4 发布了两项填补构建管道长期缺口的功能：Crucible 自动模式——在每次 forge 时自动重新生成测试脚手架，无需手动步骤；以及 Slag 检测——在整个工作空间依赖图中查找未使用的依赖。两者即日可用。

## Crucible 自动模式

Crucible 从源文件生成测试脚手架。此前，每当模块变更时你需要手动运行 `foundry crucible generate`。如果忘了，脚手架就和源码产生偏移，测试会因为错误的原因而失败。

自动模式消除了手动步骤。启用后，Crucible 会挂钩到 forge 管道中，为自上次构建以来所有变更的模块重新生成脚手架。重新生成发生在测试阶段之前，因此测试始终基于最新的脚手架运行。

```text title="在 foundry.config 中启用自动模式"
crucible {
  auto = true
  scope = "changed"   # 仅对变更的模块重新生成
  strategy = "merge"  # 保留自定义测试逻辑，更新脚手架
}
```

`merge` 策略是默认值。它更新脚手架的生成部分，同时保留你在生成标记之间添加的自定义测试逻辑。如果你偏好每次都干净地重新生成，可以设置 `strategy = "overwrite"`。

### 性能

自动模式对 forge 管道几乎没有额外耗时。Crucible 只为变更的模块重新生成脚手架，而脚手架生成速度很快——通常每个模块不到 200 毫秒。在一个有 90 个包、其中 5 个发生变更的工作空间中，自动模式大约给构建增加 1 秒。

## Slag 检测

每个单体仓库都会累积未使用的依赖。某次探索中添加了一个包，代码删掉了，依赖却留在了清单里。把这乘以 90 个包，你的安装步骤就有了一笔可观的死重。

Slag 扫描整个工作空间依赖图，报告每一个已声明但从未导入的依赖。它同时检查 `dependencies` 和 `devDependencies`，并且理解重新导出——一个仅通过桶文件消费的依赖不会被标记为未使用。

```text title="运行 Slag"
foundry slag detect
```

```text title="示例输出"
demo-api
  lodash.merge     声明在 dependencies 中，从未导入
  @types/express   声明在 devDependencies 中，从未导入

demo-web
  chalk            声明在 dependencies 中，从未导入

2 个包中共有 3 个未使用的依赖
```

### 自动移除

Slag 可以使用 `--fix` 标志自动移除未使用的依赖。它在单步中更新清单并运行锁文件解析：

```text title="自动移除"
foundry slag detect --fix
```

Slag 不会触碰对等依赖。对等依赖可能被下游包消费，移除它可能以本地不可见的方式破坏解析图。

## 升级

Foundry 2.4 向后兼容。Crucible 自动模式通过配置文件选择启用。Slag 是一个新命令，不影响现有工作流。

```text title="升级"
spark upgrade foundry-cli
foundry --version
# foundry-cli 2.4.0
```
