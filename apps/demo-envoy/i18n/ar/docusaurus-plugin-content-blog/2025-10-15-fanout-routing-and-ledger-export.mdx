يضيف Envoy 2.2 ميزتين تغيّران طريقة بناء الفرق لخطوط المرحّلات: التوزيع المروحي في Dispatch، الذي يرسل رسالة واردة واحدة إلى وجهات متعددة في آنٍ واحد، وتصدير Ledger، الذي يشحن مُدخلات سجل التدقيق إلى أي نقطة نهاية Spoke وفق جدول تتحكم به. كلتاهما متاحتان اليوم.

## التوزيع المروحي في Dispatch

حتى الآن، اتبع Dispatch نموذج التطابق الأول. الرسالة الواردة تطابق مساراً واحداً وتُسلَّم إلى وجهة واحدة. إذا كنت تحتاج نفس الرسالة في ثلاثة أماكن، كتبت ثلاثة مُرحّلات.

التوزيع المروحي يغيّر ذلك. يستطيع مُرحّل واحد الآن الإعلان عن وجهات Spoke متعددة. حين تطابق رسالة المسار، يسلّمها Dispatch إلى كل Spoke معلَن بالتوازي.

```text title="بيان مُرحّل مروحي"
relay "order-events" {
  source "shopfront-webhook" {
    cipher = "hmac-sha256"
  }

  dispatch {
    mode = "fanout"

    spoke "warehouse-api" {
      parcel = "json-to-xml"
    }

    spoke "analytics-pipeline" {
      parcel = "json-to-json"
    }

    spoke "slack-alerts" {
      parcel = "json-to-plaintext"
      filter = "$.event.type == 'order.cancelled'"
    }
  }
}
```

كل Spoke في مُرحّل مروحي يحصل على تحويل Parcel خاص ومرشّح اختياري. المستودع يستقبل XML، وخط التحليلات يستقبل JSON، وSlack لا يستقبل إلا أحداث الإلغاء كنص عادي. webhook واردة واحدة تغذّي الثلاثة جميعاً.

### دلالات التسليم

تسليم التوزيع المروحي مستقل لكل Spoke. إذا أعاد واجهة المستودع البرمجية خطأ 500، يعيد Courier محاولة ذلك التسليم دون التأثير على الآخرَين. يسجّل Ledger تسليم كل Spoke كمعاملة مستقلة، فتستطيع تتبّع حالة كل وجهة بشكل مستقل.

### الأداء

لا يضيف التوزيع المروحي أي تأخير قابل للقياس. يحلّل Dispatch جميع وجهات Spoke عند تطابق المسار ويسلّمها لـ Courier كمهام تسليم متوازية. مُرحّل بخمس وجهات Spoke يسلّم في نفس نافذة p99 كمُرحّل بوجهة واحدة.

## تصدير Ledger

سجّل Ledger دائماً كل رسالة تم استقبالها وتحويلها وتوجيهها وتسليمها. حتى الآن، كانت الطريقة الوحيدة للوصول إلى تلك البيانات عبر واجهة Ledger البرمجية أو لوحة Glassboard.

تصدير Ledger يغيّر ذلك. تستطيع الآن تهيئة Ledger لشحن المُدخلات إلى أي نقطة نهاية Spoke وفق جدول. فرق الامتثال تحصل على بيانات التدقيق في نظام SIEM الخاص بهم. فرق التحليلات تحصل على مقاييس التسليم في مستودع بياناتهم. فرق العمليات تحصل على تقارير الأعطال في أداة إدارة الحوادث.

```text title="تهيئة تصدير Ledger"
ledger {
  retention = "90d"

  export "compliance-siem" {
    spoke    = "siem-ingest"
    schedule = "every 1h"
    filter   = "status IN ('failed', 'dead-letter')"
    format   = "json-lines"
  }

  export "analytics-warehouse" {
    spoke    = "bigquery-ingest"
    schedule = "every 6h"
    filter   = "*"
    format   = "parquet"
  }
}
```

كل إعلان تصدير يحدّد Spoke وجهة وجدولاً ومرشّحاً اختيارياً وتنسيق إخراج. التنسيقات المدعومة هي JSON Lines وCSV وParquet. التصدير تزايدي: كل عملية تشحن فقط المُدخلات المسجّلة منذ العملية السابقة.

### إعادة التعبئة

للنشرات القائمة، يدعم تصدير Ledger أمر إعادة تعبئة لمرة واحدة يصدّر المُدخلات التاريخية حتى نافذة الاحتفاظ المهيّأة:

```text title="أمر إعادة التعبئة"
envoy ledger export --backfill --target compliance-siem
```

## الترقية

Envoy 2.2 متوافق مع الإصدارات السابقة. بيانات المُرحّلات الحالية تستمر في العمل دون تغييرات. الوضع المروحي اختياري لكل مُرحّل. تصدير Ledger اختياري لكل نشرة.

```text title="الترقية"
vial pull envoy:2.2
envoy --version
# envoy 2.2.0
```
