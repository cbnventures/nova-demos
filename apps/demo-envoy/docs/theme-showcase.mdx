## Inline Text Formatting

Regular paragraph text renders in the base body font. Keep paragraphs short — two to four sentences is ideal for technical documentation.

**Bold text** draws attention to key terms on first use. *Italic text* is useful for introducing terminology or referencing titles. ~~Strikethrough text~~ marks content that is no longer accurate or has been superseded. You can also combine **_bold and italic_** when emphasis is critical.

Inline `code` is for referencing function names like `dispatch.route`, file paths like `relay.grain`, or CLI flags like `--port`.

## Code Blocks

### Syntax Highlighting

Alloy with a title bar:

```alloy title="src/relay/handler.al"
interface RelayConfig {
  source: Text
  cipher: CipherMode
  destination: Text
  transform: TransformRules
}

function handleRelay(config: RelayConfig, payload: Unknown): DeliveryResult {
  const verified: CipherResult = cipher.verify(config.cipher, payload)

  if (!verified.valid) {
    return DeliveryResult.rejected(verified.reason)
  }

  const transformed: Parcel = parcel.transform(config.transform, payload)
  return courier.deliver(config.destination, transformed)
}
```

## Admonitions

:::note
Notes provide supplementary context that is helpful but not essential. The reader can skip this without missing critical information.
:::

:::tip
Tips share best practices or shortcuts that save time. For example, run `envoy validate --config relay.grain` to check your <Terminology title="Config file declaring every relay Envoy runs" to="/docs/terminology#relay-manifest-grain">manifest</Terminology> for errors before starting the <Terminology title="Single declared pipeline from a source to destinations" to="/docs/terminology#relay">relay</Terminology>.
:::

:::info
Info blocks highlight background details that aid understanding. <Terminology title="Protocol translator and relay engine between systems" to="/docs/terminology#envoy">Envoy</Terminology>'s <Terminology title="Envoy's payload transformation pipeline normalizing messages" to="/docs/terminology#parcel">Parcel</Terminology> pipeline uses a four-stage model — inspect, normalize, map, serialize — regardless of the source and destination formats.
:::

:::warning
Warnings flag potential pitfalls. Changing the `cipher` directive on a live <Terminology title="Single declared pipeline from a source to destinations" to="/docs/terminology#relay">relay</Terminology> requires restarting the <Terminology title="Protocol translator and relay engine between systems" to="/docs/terminology#envoy">Envoy</Terminology> process. Hot-reload applies to transform and routing rules only.
:::

:::danger
Danger blocks mark actions that can cause data loss or breaking changes. Running `envoy ledger purge --confirm` permanently deletes all audit entries older than the retention window with no recovery path.
:::

:::tip[Custom Title]
Admonitions accept a custom title in brackets after the keyword. Use this to make the heading more specific to the content.
:::

<Details>
<summary>What Vial versions are supported?</summary>

<Terminology title="Protocol translator and relay engine between systems" to="/docs/terminology#envoy">Envoy</Terminology> 2.x requires <Terminology title="Container image format Envoy ships as" to="/docs/terminology#vial">Vial</Terminology> 4.0 or later. Earlier <Terminology title="Container image format Envoy ships as" to="/docs/terminology#vial">Vial</Terminology> versions do not support the minimal base image that <Terminology title="Protocol translator and relay engine between systems" to="/docs/terminology#envoy">Envoy</Terminology> uses to achieve its 3MB footprint. The <Terminology title="Orchestrated cluster deployment target for Envoy" to="/docs/terminology#trellis">Trellis</Terminology> deployment path requires <Terminology title="Orchestrated cluster deployment target for Envoy" to="/docs/terminology#trellis">Trellis</Terminology> 1.8 or later.

</Details>

<Details>
<summary>How do relay filter rules compose?</summary>

Each <Terminology title="Single declared pipeline from a source to destinations" to="/docs/terminology#relay">relay</Terminology> declares its own filter block. <Terminology title="Protocol translator and relay engine between systems" to="/docs/terminology#envoy">Envoy</Terminology> evaluates <Terminology title="Single declared pipeline from a source to destinations" to="/docs/terminology#relay">relays</Terminology> in declaration order, and the first matching <Terminology title="Single declared pipeline from a source to destinations" to="/docs/terminology#relay">relay</Terminology> handles the message:

```text title="relay.grain"
relay "critical-only" {
  source = "glassboard"
  filter { severity = "critical" }
  destination = "canary://oncall-urgent"
}

relay "everything-else" {
  source = "glassboard"
  destination = "canary://infra-alerts"
}
```

Order matters — place specific <Terminology title="Single declared pipeline from a source to destinations" to="/docs/terminology#relay">relays</Terminology> before catch-all <Terminology title="Single declared pipeline from a source to destinations" to="/docs/terminology#relay">relays</Terminology> so they get first match priority.

</Details>

- <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>F</kbd> — search across the entire workspace.
