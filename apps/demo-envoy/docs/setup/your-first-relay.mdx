# Your First Relay

This walkthrough takes you from a fresh <Terminology title="Protocol translator and relay engine between systems" to="/docs/terminology#envoy">Envoy</Terminology> install to a working <Terminology title="Single declared pipeline from a source to destinations" to="/docs/terminology#relay">relay</Terminology> that receives a <Terminology title="Source code hosting platform with a built-in translator" to="/docs/terminology#threadbare">Threadbare</Terminology> code push webhook, transforms it into a readable notification, and delivers it to <Terminology title="Uptime monitoring service used as an example destination" to="/docs/terminology#canary">Canary</Terminology>.

## Step 1: Write the Relay Manifest

Create a `relay.grain` file in your working directory. This <Terminology title="Config file declaring every relay Envoy runs" to="/docs/terminology#relay-manifest-grain">manifest</Terminology> defines one <Terminology title="Single declared pipeline from a source to destinations" to="/docs/terminology#relay">relay</Terminology>: <Terminology title="Source code hosting platform with a built-in translator" to="/docs/terminology#threadbare">Threadbare</Terminology> push events routed to a <Terminology title="Uptime monitoring service used as an example destination" to="/docs/terminology#canary">Canary</Terminology> topic.

```text title="relay.grain"
relay "threadbare-pushes" {
  source = "threadbare"
  // highlight-next-line
  cipher = "hmac-sha256"

  transform {
    // highlight-start
    title = "[{{ repo }}] {{ count }} new commit(s) to {{ branch }}"
    body  = "{{ author }} pushed to {{ branch }}:\n{{ commit_summary }}"
    // highlight-end
    priority = 3
    tags     = ["package"]
  }

  destination = "canary://ci-builds"

  retry {
    strategy = "exponential"
    max      = 5
  }
}
```

The `cipher` directive tells <Terminology title="Protocol translator and relay engine between systems" to="/docs/terminology#envoy">Envoy</Terminology> to validate the incoming webhook using HMAC-SHA256 signatures. <Terminology title="Source code hosting platform with a built-in translator" to="/docs/terminology#threadbare">Threadbare</Terminology> signs every webhook payload with the secret you configure on their side.

## Step 2: Start the Relay

Start <Terminology title="Protocol translator and relay engine between systems" to="/docs/terminology#envoy">Envoy</Terminology> with the <Terminology title="Config file declaring every relay Envoy runs" to="/docs/terminology#relay-manifest-grain">manifest</Terminology>:

```bash title="Start Envoy"
envoy start --config relay.grain --port 8090
```

<Terminology title="Protocol translator and relay engine between systems" to="/docs/terminology#envoy">Envoy</Terminology> reads the <Terminology title="Config file declaring every relay Envoy runs" to="/docs/terminology#relay-manifest-grain">manifest</Terminology>, initializes <Terminology title="Envoy's authentication gateway verifying every request" to="/docs/terminology#cipher">Cipher</Terminology> with the HMAC verification mode, compiles the <Terminology title="Envoy's payload transformation pipeline normalizing messages" to="/docs/terminology#parcel">Parcel</Terminology> transformation template, and registers the <Terminology title="Envoy's routing engine deciding message destinations" to="/docs/terminology#dispatch">Dispatch</Terminology> route.

## Step 3: Configure the Source

In your <Terminology title="Source code hosting platform with a built-in translator" to="/docs/terminology#threadbare">Threadbare</Terminology> repository settings, add a webhook:

- **Payload URL:** `https://your-envoy-host:8090/relay/threadbare`
- **Content type:** `application/json`
- **Secret:** The same secret <Terminology title="Protocol translator and relay engine between systems" to="/docs/terminology#envoy">Envoy</Terminology> uses for HMAC validation
- **Events:** Select "Just the push event"

## Step 4: Push a Commit

Push a commit to the repository. <Terminology title="Source code hosting platform with a built-in translator" to="/docs/terminology#threadbare">Threadbare</Terminology> fires the webhook. <Terminology title="Protocol translator and relay engine between systems" to="/docs/terminology#envoy">Envoy</Terminology> receives it:

```json title="Incoming Threadbare payload"
{
  "ref": "refs/heads/main",
  "repository": { "full_name": "acme/web-app" },
  "pusher": { "name": "nneka" },
  "commits": [
    { "id": "a7f3c9d", "message": "Fix rate limiter edge case" },
    { "id": "b2e8f1a", "message": "Update Courier retry defaults" }
  ]
}
```

<Terminology title="Envoy's payload transformation pipeline normalizing messages" to="/docs/terminology#parcel">Parcel</Terminology> transforms it into the <Terminology title="Uptime monitoring service used as an example destination" to="/docs/terminology#canary">Canary</Terminology> format:

```json title="Transformed Canary notification"
{
  "title": "[acme/web-app] 2 new commit(s) to main",
  "body": "nneka pushed to main:\n- a7f3c9d: Fix rate limiter edge case\n- b2e8f1a: Update Courier retry defaults",
  "priority": 3,
  "tags": ["package"]
}
```

<Terminology title="Envoy's guaranteed-delivery engine with retry backoff" to="/docs/terminology#courier">Courier</Terminology> delivers it to the `ci-builds` <Terminology title="Uptime monitoring service used as an example destination" to="/docs/terminology#canary">Canary</Terminology> topic and records a delivery receipt in <Terminology title="Append-only audit log of every message's state" to="/docs/terminology#ledger">Ledger</Terminology>.

## Step 5: Verify in Ledger

Query the <Terminology title="Append-only audit log of every message's state" to="/docs/terminology#ledger">Ledger</Terminology> to confirm the delivery:

```bash title="Query Ledger"
curl http://localhost:8090/api/deliveries?relay=threadbare-pushes&limit=1
```

```json title="Ledger response"
{
  "deliveries": [
    {
      "id": "msg_f7a2b8c4",
      "relay": "threadbare-pushes",
      "status": "delivered",
      "attempts": 1,
      "latency_ms": 3.1,
      "timestamp": "2025-03-01T14:22:07Z"
    }
  ]
}
```

:::tip
Run `envoy status` from the CLI to see a live summary of all active <Terminology title="Single declared pipeline from a source to destinations" to="/docs/terminology#relay">relays</Terminology>, their delivery rates, and any messages currently in retry or <Terminology title="Terminal state after Courier's retries are exhausted" to="/docs/terminology#dead-letter">dead-letter</Terminology> state.
:::
