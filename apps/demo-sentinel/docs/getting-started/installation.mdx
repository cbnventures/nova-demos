# Installation

Sentinel requires an agent on every endpoint that participates in the trust evaluation loop. The agent communicates with the Sentinel <Terminology title="Sentinel service that agents register with and report to" to="/docs/terminology#control-plane">control plane</Terminology> over <Terminology title="Tunnel protocol connecting an agent to the control plane" to="/docs/terminology#filament">Filament</Terminology> tunnels and reports device posture to <Terminology title="Continuous posture assessment engine computing the trust score" to="/docs/terminology#watchtower">Watchtower</Terminology>.

## Prerequisites

- **<Terminology title="CLI used to install the Sentinel agent" to="/docs/terminology#spark">Spark</Terminology> CLI** 2.0 or later (for <Terminology title="CLI used to install the Sentinel agent" to="/docs/terminology#spark">Spark</Terminology> installation method)
- **<Terminology title="Tunnel protocol connecting an agent to the control plane" to="/docs/terminology#filament">Filament</Terminology>** protocol support on the host network (UDP 51820)
- A Sentinel <Terminology title="Sentinel service that agents register with and report to" to="/docs/terminology#control-plane">control plane</Terminology> instance (cloud-hosted or self-managed)

:::warning Filament Protocol Version
Sentinel 3.x requires <Terminology title="Tunnel protocol connecting an agent to the control plane" to="/docs/terminology#filament">Filament</Terminology> protocol version 2.0 or later. Older <Terminology title="Tunnel protocol connecting an agent to the control plane" to="/docs/terminology#filament">Filament</Terminology> implementations do not support the encrypted posture telemetry channel that <Terminology title="Endpoint compliance engine that enrolls and enforces device policy" to="/docs/terminology#garrison">Garrison</Terminology> uses for device health reporting. Verify your <Terminology title="Tunnel protocol connecting an agent to the control plane" to="/docs/terminology#filament">Filament</Terminology> version with `filament --version` before proceeding.
:::

## Install the Agent

<Tabs>
<TabItem value="spark" label="Spark" default>

```bash title="Install via Spark"
spark install sentinel-agent
```

<Terminology title="CLI used to install the Sentinel agent" to="/docs/terminology#spark">Spark</Terminology> resolves the correct binary for your operating system and architecture. The agent is installed to `~/.spark/bin/sentinel-agent` and added to your PATH automatically.

```bash title="Verify installation"
sentinel-agent --version
```

</TabItem>
<TabItem value="vial" label="Vial Container">

```bash title="Pull the Sentinel agent image"
vial pull sentinel/agent:latest
```

Run the agent as a long-lived container:

```bash title="Run the agent container"
vial run -d \
  --name sentinel-agent \
  --restart always \
  --cap-add NET_ADMIN \
  -v /var/lib/sentinel:/data \
  sentinel/agent:latest
```

The `NET_ADMIN` capability is required for <Terminology title="Tunnel protocol connecting an agent to the control plane" to="/docs/terminology#filament">Filament</Terminology> tunnel management.

</TabItem>
<TabItem value="arcline" label="Arcline Marketplace">

```bash title="Deploy from Arcline Marketplace"
arcline deploy sentinel-agent \
  --region us-east-1 \
  --tier standard \
  --auto-enroll
```

The <Terminology title="Cloud marketplace deployment target for Sentinel" to="/docs/terminology#arcline">Arcline</Terminology> marketplace deployment includes automatic <Terminology title="Endpoint compliance engine that enrolls and enforces device policy" to="/docs/terminology#garrison">Garrison</Terminology> enrollment and <Terminology title="Tunnel protocol connecting an agent to the control plane" to="/docs/terminology#filament">Filament</Terminology> tunnel provisioning. No additional configuration is required.

</TabItem>
</Tabs>

## Register with the Control Plane

After installation, register the agent with your Sentinel <Terminology title="Sentinel service that agents register with and report to" to="/docs/terminology#control-plane">control plane</Terminology>:

```bash title="Agent registration"
sentinel-agent register \
  --control-plane sentinel.yourcompany.internal \
  --enrollment-token $SENTINEL_ENROLLMENT_TOKEN
```

The agent performs an initial posture check during registration. <Terminology title="Endpoint compliance engine that enrolls and enforces device policy" to="/docs/terminology#garrison">Garrison</Terminology> records the baseline device state — OS version, disk encryption status, firewall configuration, and installed patch level.

```text title="Registration output"
Registering with control plane: sentinel.yourcompany.internal
  Device ID:       dev_a3b7c9d1e5f2
  Filament tunnel: established (UDP 51820)
  Posture baseline: captured
    OS:             macOS 15.2
    Encryption:     FileVault enabled (AES-256)
    Firewall:       active
    Patch level:    current

Registration complete. Watchtower evaluation begins in 90s.
```

:::note Enrollment Tokens
Enrollment tokens are single-use and expire after 24 hours. Generate new tokens from the Sentinel dashboard or via the <Terminology title="Sentinel's REST API for policy and device management" to="/docs/terminology#spoke-api">Spoke API</Terminology>: `sentinel api tokens create --type enrollment --ttl 24h`.
:::

## Post-Installation

Once registered, the agent operates autonomously:

- **<Terminology title="Endpoint compliance engine that enrolls and enforces device policy" to="/docs/terminology#garrison">Garrison</Terminology>** checks device posture on a continuous loop and reports to the <Terminology title="Sentinel service that agents register with and report to" to="/docs/terminology#control-plane">control plane</Terminology>.
- **<Terminology title="Continuous posture assessment engine computing the trust score" to="/docs/terminology#watchtower">Watchtower</Terminology>** evaluates the agent's posture data against active trust policies every 90 seconds.
- **<Terminology title="Adaptive access gateway granting or revoking access" to="/docs/terminology#drawbridge">Drawbridge</Terminology>** grants or revokes <Terminology title="Tunnel protocol connecting an agent to the control plane" to="/docs/terminology#filament">Filament</Terminology> tunnel access based on the evaluation result.

No manual intervention is required after enrollment. Policy changes propagate to enrolled agents automatically.
